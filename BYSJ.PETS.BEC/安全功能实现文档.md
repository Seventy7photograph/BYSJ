# 安全功能实现文档

## 1. 分布式锁实现

### 1.1 实现方式
- **基于Redis的分布式锁**
- 使用Redis的`setIfAbsent`命令实现原子操作
- 支持锁的获取、释放、超时处理及异常恢复机制

### 1.2 核心类
- `RedisDistributedLockUtil.java`：分布式锁工具类

### 1.3 主要方法
- `acquireLock(String lockKey, String requestId, long expireTime)`：获取分布式锁
- `releaseLock(String lockKey, String requestId)`：释放分布式锁
- `tryAcquireLock(String lockKey, String requestId, long expireTime, int retryTimes, long retryInterval)`：尝试获取分布式锁，带重试机制
- `isLockExist(String lockKey)`：检查锁是否存在
- `extendLockExpireTime(String lockKey, String requestId, long expireTime)`：延长锁的过期时间

### 1.4 使用示例
```java
// 生成唯一的请求标识
String requestId = UUID.randomUUID().toString();
// 尝试获取锁，最多重试3次，每次间隔100ms
boolean acquired = redisDistributedLockUtil.tryAcquireLock("product:123:stock", requestId, 30, 3, 100);
if (acquired) {
    try {
        // 执行业务逻辑
        // ...
    } finally {
        // 释放锁
        redisDistributedLockUtil.releaseLock("product:123:stock", requestId);
    }
}
```

## 2. 敏感数据脱敏功能

### 2.1 支持的脱敏类型
- 手机号：保留前3位和后4位，中间用*代替
- 身份证号：保留前6位和后4位，中间用*代替
- 银行卡号：保留前4位和后4位，中间用*代替
- 姓名：单字名保留姓氏，多字名保留姓氏和最后一个字
- 邮箱：保留用户名的前3位和域名，中间用*代替
- 地址：保留前10个字符，后面用*代替
- 密码：全部用*代替

### 2.2 核心类
- `SensitiveDataMaskUtil.java`：敏感数据脱敏工具类

### 2.3 主要方法
- `mask(String data, MaskType type)`：统一的敏感数据脱敏方法
- `maskPhone(String phone)`：手机号脱敏
- `maskIdCard(String idCard)`：身份证号脱敏
- `maskBankCard(String bankCard)`：银行卡号脱敏
- `maskName(String name)`：姓名脱敏
- `maskEmail(String email)`：邮箱脱敏
- `maskAddress(String address)`：地址脱敏
- `maskPassword(String password)`：密码脱敏
- `maskCustom(String data, int start, int end, char maskChar)`：自定义脱敏

### 2.4 使用示例
```java
// 手机号脱敏
String maskedPhone = sensitiveDataMaskUtil.mask("13812345678", SensitiveDataMaskUtil.MaskType.PHONE);
// 输出：138****5678

// 身份证号脱敏
String maskedIdCard = sensitiveDataMaskUtil.mask("110101199001011234", SensitiveDataMaskUtil.MaskType.ID_CARD);
// 输出：110101********1234
```

## 3. SQL注入防护增强

### 3.1 实现方式
- 基于正则表达式的SQL注入检测
- 输入验证和过滤机制
- SQL注入检测日志记录

### 3.2 核心类
- `SqlInjectionUtil.java`：SQL注入防护工具类

### 3.3 主要方法
- `containsSqlInjection(String input)`：检测输入是否包含SQL注入风险
- `filterSqlInjection(String input)`：过滤SQL注入风险字符
- `isValidInput(String input, int maxLength)`：验证输入是否安全
- `sanitizeInput(String input, int maxLength)`：清理和验证输入

### 3.4 使用示例
```java
// 验证输入是否安全
if (!sqlInjectionUtil.isValidInput(userInput, 100)) {
    throw new IllegalArgumentException("输入包含不安全内容");
}

// 清理输入
String sanitizedInput = sqlInjectionUtil.sanitizeInput(userInput, 100);
// 使用清理后的输入进行数据库操作
```

## 4. XSS攻击防护实现

### 4.1 实现方式
- 前端：输入验证和输出编码
- 后端：响应内容的HTML转义处理
- 配置适当的Content-Security-Policy头信息
- 实现Cookie的HttpOnly和Secure属性设置

### 4.2 核心类
- 后端：`XssProtectionUtil.java`：XSS攻击防护工具类
- 后端：`SecurityHeaderFilter.java`：安全头信息过滤器
- 前端：`xssProtection.js`：前端XSS防护工具函数

### 4.3 主要方法
- 后端：
  - `containsXss(String input)`：检测输入是否包含XSS风险
  - `filterXss(String input)`：过滤XSS风险字符
  - `escapeHtml(String input)`：HTML转义，防止XSS攻击
  - `sanitizeInput(String input, int maxLength)`：清理和验证输入，防止XSS攻击
- 前端：
  - `containsXss(input)`：检测输入是否包含XSS风险
  - `filterXss(input)`：过滤XSS风险字符
  - `escapeHtml(input)`：HTML转义，防止XSS攻击
  - `sanitizeInput(input, maxLength)`：清理和验证输入，防止XSS攻击
  - `isValidInput(input, maxLength)`：验证输入是否安全

### 4.4 使用示例
- 后端：
```java
// 验证输入是否安全
if (!xssProtectionUtil.containsXss(userInput)) {
    // 处理安全输入
} else {
    throw new IllegalArgumentException("输入包含XSS攻击风险");
}

// 清理输入
String sanitizedInput = xssProtectionUtil.sanitizeInput(userInput, 100);
// 使用清理后的输入
```

- 前端：
```javascript
import { sanitizeInput, isValidInput } from '@/utils/xssProtection';

// 验证输入是否安全
if (!isValidInput(userInput, 100)) {
    alert('输入包含不安全内容');
    return;
}

// 清理输入
const sanitizedInput = sanitizeInput(userInput, 100);
// 使用清理后的输入
```

## 6. 注意事项

1. **分布式锁**：
   - 锁的过期时间应根据业务逻辑的执行时间合理设置
   - 必须在finally块中释放锁，确保锁能够被正确释放
   - 避免长时间持有锁，影响系统性能

2. **敏感数据脱敏**：
   - 脱敏处理应在数据展示和日志记录时使用，不应影响业务逻辑
   - 对于需要精确匹配的场景（如登录、支付），不应使用脱敏处理

3. **SQL注入防护**：
   - 优先使用MyBatis Plus的参数绑定功能，避免直接拼接SQL
   - 对于动态SQL，应使用MyBatis的#{}占位符
   - 定期检查数据库操作代码，确保没有使用不安全的SQL拼接

4. **XSS攻击防护**：
   - 前端和后端都应实现XSS防护，形成双重保障
   - 对于富文本编辑器等特殊场景，应使用专业的XSS过滤库
   - 定期更新Content-Security-Policy配置，适应新的安全威胁

## 7. 总结

本系统实现了四种安全功能增强：
1. **分布式锁**：基于Redis实现，确保分布式环境下的资源竞争安全
2. **敏感数据脱敏**：支持多种敏感数据类型的脱敏处理
3. **SQL注入防护**：通过输入验证和过滤机制，防止SQL注入攻击
4. **XSS攻击防护**：通过前后端双重防护，防止XSS攻击

这些安全功能的实现，大大提高了系统的安全性，保护了用户数据和系统资源。同时，通过详细的单元测试和文档，确保了功能的有效性和可维护性。
